# NPC interaction

The Barbarian prefab starts an interaction when the player enters `NpcProximityTrigger.interactionRadius`. Set `SpeechText` on the Behavior Graph Agent’s Blackboard for a first-time greeting; the profile supplies returning-player and memory-unavailable greetings. Staying outside range for `departureGraceSeconds` (one second by default) cancels the interaction; entering again after that starts it again. Brief boundary crossings preserve the current speech. After speech finishes, the NPC keeps facing the player while they remain nearby, without repeating the line.

`Assets/_Behavior/NPC.asset` receives the interaction event and runs `Conversation.asset`. That subgraph keeps greeting and conversation inside `FacePlayerDuringInteraction`, which restores the previous facing settings and smoothly turns back to the saved pose when the interaction ends. The conversation loop keeps that scope open until departure is confirmed. The return uses the facing component’s turn duration and can be interrupted by a new interaction. `SpeakText` stops its own playback when it ends. The proximity trigger only publishes the player and interaction state; it contains no facing or speech behavior.

`SpeakText` accepts a speaker and arbitrary text. It uses `BaseAI_TextToSpeech` for playback, activity, and cancellation. The current prefab uses Wit; the graph node has no Wit dependency or greeting-specific behavior. Playback uses the original Wit UnityAudioPlayer and its default readiness threshold. Greeting recognition requires the Node service and PostgreSQL; when memory cannot be loaded, a neutral greeting avoids claiming this is a first meeting. Playback requires Wit access. Answering a question additionally requires model access.

When the speaker has an `NpcSpeechOutput`, `SpeakText` publishes the spoken text there and clears it when speech completes or is cancelled. The separate `NpcSpeechCaptionView` renders that state through the existing `UI_TextDisplay`.

The graphs use Unity Behavior 1.0.16 and can be edited in Unity's Behavior window.

Run the `NpcInteraction.Tests` EditMode assembly in Unity Test Runner. Its `LiveWit` test enters Play Mode with the actual prefab and checks approach, facing, departure cancellation, repeat interaction, and return to idle. It requires working Wit configuration and service access. Test playback is muted and the previous listener volume is restored afterward.

## Profile conversation

The Barbarian now has an `NpcCharacterDirector`, `NpcProxyClient`, and a `BarbarianProfile` asset. Edit the profile's personality, permitted facts, restrictions, fallback and voice preset in `Assets/_Behavior/BarbarianProfile.asset`. `NpcWitVoiceBinding` applies that voice preset to the existing Wit speaker.

The Conversation graph opens an interaction, selects the NPC when no other NPC is selected, faces the player, loads memory, and chooses its greeting. The authored `Succeeder` lets a failed greeting continue to listening. It then repeats **Wait For NPC Transcript → Try In Order [Load Memory → Commit Input → Request → Remember Speech [Speak], Request Fallback → Remember Speech [Speak]]**. `NpcTurnScope` cancels its child branch when the selection revision changes, including an A → B → A switch within one frame. Request and speech nodes stop their own adapters when the graph ends them. `NpcCharacterDirector` holds interaction and selection state and coordinates campaign reset; normal conversation sequencing belongs to the graph.

`Transcript`, `Response`, `RequestError`, `SpeechResult`, and `SpeechError` are transient Blackboard values. A failed request returns failure with its error code; the separate authored fallback branch reads the profile's unavailable reply. Cancellation never selects that fallback. Speech results distinguish completed playback, failure, and cancellation; a caption is not evidence of audio delivery. A speech failure ends that turn and the repeat node returns to listening. Player input is committed before model generation. Only completed playback is restored as NPC speech; interrupted or failed playback records its status with no unconfirmed text.

`NPC/Set Up Profile Conversation` repairs missing references while preserving authored graphs and values. Edit behavior in Unity’s Behavior window; use source control for rollback.

The scene's `NPC Speech Input` uses the current Wit SDK through `NpcWitTranscription`. In the Editor, enter Play Mode, approach the Barbarian, wait for its greeting, click **Talk to NPC**, and ask “Where can I get lodging for the night?”. Click **Finish speaking** or let Wit finalize the utterance. On Quest, hold the right index trigger to record and release to finish; the controller and `InputXR` button are configurable on `NpcSpeechControls`. One NPC owns the active conversation until departure; gameplay may explicitly call `SelectForConversation` to choose another nearby NPC. A recording captures its recipient and interaction at its start, and late transcripts are discarded after departure or selection change.

Start the local service using [the service instructions](../../../../Server/npc-service/README.md). Provider credentials belong only in `Server/npc-service/.env`. Editor connection settings live in ignored `UserSettings/NpcService.local.json`; player builds use Meta Platform user proof instead.

`NpcConversationPlayTests` covers real-model Wit playback and departure cancellation, plus unavailable-server recovery and single-recipient routing. Real-model tests require the local service and Wit access. They mute the listener during automated playback and restore the previous scene, listener volume, and background-execution setting.

The headset displays recording and processing status below the center of view, with partial recognized words during capture. The Wit configuration disables unused intent-attribute dispatch to avoid an assembly scan during Quest startup. For USB testing without a Meta Platform app, use the development-only setup in `Server/npc-service/README.md`.

The recording display is the nested `Assets/_Prefabs/NpcSpeechStatus.prefab`. Edit its Canvas/TMP layout and `NpcSpeechStatusView` fields for wording, colors, camera offset, and failure-display duration. `NpcSpeechInput` only routes capture and exposes provider-neutral status; `NpcWitTranscription` implements `INpcSpeechCaptureStatus`. Red RECORDING follows the provider's actual recording state.

## Reskinning controls and speech output

- **Mic controls:** replace or disable `NpcSpeechControls` on `NpcSpeechInput.prefab` and the standalone `NPC Speech Input` object in `BaseScene`. A UI button, gesture, or controller adapter calls `NpcSpeechInput.BeginListening()` and `EndListening()`. Read `CanBeginListening`, `HasRecipient`, and `IsListening` to enable and label controls. The input component retains recipient/turn checks, timeout, and cancellation; custom controls must not call the transcription provider directly. Disabling the default controls while its XR button is held finishes that capture.
- **Mic status:** replace `NpcSpeechStatusView` and its nested prefab independently. Read the input's recording, starting, processing (`IsListening` after capture), partial-transcript, and failure state. Recording indicators must reflect `IsRecording`, not button-down state.
- **NPC output:** keep `NpcSpeechOutput` on the graph's speaker GameObject. Replace or disable `NpcSpeechCaptionView` to change the renderer or location. A custom view reads `output.Text` when enabled, subscribes to `output.Changed`, and unsubscribes when disabled. A null text means clear the display. Hiding a view does not cancel audio or erase the output state; re-enabling it restores the current text. Keep the view outside any panel it hides.

The current caption view references `UI_TextDisplay`; a replacement can render TMP text, a speech bubble, or a HUD without changing `SpeakText`. Output text becomes available when speech is requested, just as captions did before; it is not proof that audio has started or completed. The graph and speech adapter remain responsible for playback results and cancellation. `NpcCharacterDirector`, the conversation graphs, transcript routing, and the service request contract do not need to change for a reskin.

## Persistent conversation (US-03)

`Conversation.asset` runs the authored `Memory.asset` subgraph before greeting. `LoadNpcMemory` only loads acknowledged state through `NpcMemory` and the proxy. The separate `ChooseNpcGreeting` action chooses authored profile text from that state; `SpeakText` performs playback. Prior finalized player speech establishes recognition; entering proximity and hearing a greeting alone do not. The existing departure grace period still governs when another greeting begins.

`NpcCampaign` persists a campaign UUID per world and a writer UUID per installation in PlayerPrefs. On Quest, the panel above the left controller shows **Hold X to reset campaign**. Hold the left controller’s X button for two seconds; progress appears during the hold, releasing early cancels, and a completed hold shows a confirmation. Continued holding cannot trigger another reset. The Editor/desktop also retains its **Reset campaign** button. Both inputs call `NpcCampaignControls.ResetCampaign()`, which delegates to the director’s campaign operation: cancel the old interaction and reload fresh state. Previous campaigns remain stored. `NpcCampaignStatusView` owns only the HUD presentation; controller binding, hold duration, labels, controller anchor and panel offset are configurable. The view uses the rig’s tracked left-controller anchor by default, faces the camera for readability, and hides without an anchor. Reset requires the controller’s X button; no hand gesture is provided. `campaignId` on the director shows the current runtime ID; it is initialized from persistent settings rather than the authored scene value.

`NpcMemory` keeps an in-process queue of immutable event IDs and revision checks. The graph explicitly runs **Memory → CommitNpcInput → RequestNpcResponse → RememberNpcSpeech [SpeakText]**. The commit node saves exact finalized input before the generation node runs. The speech-memory scope records completion or interruption even when its child is aborted; `SpeakText` and `NpcSpeechOutput` remain generic playback and presentation components. A retry reuses the original event and receipt; load replaces the local `BaseAI_Conversation.acknowledgedHistory` projection. The legacy text-pair buffer contains completed dialogue only. All scoped history is supplied by Node, so Unity never resubmits a second copy in model requests.

Storage errors remain visible beside the reset control and do not manufacture a new history. A later interaction or question retries pending in-process commits and reloads state. Full crash/offline journaling is deferred to US-12; events not acknowledged before the application exits are not guaranteed to survive. Interrupted speech has no reliable spoken-prefix callback in the current adapter, so it records interruption without claiming the entire generated line was heard. Action execution fields remain distinct and are connected in US-08.

Run `NpcMemoryTests` for campaign identity and delivered-history projection checks. `NpcMemoryPlayTests` enters real Unity Play Mode with the shipped Barbarian prefab, local Node/PostgreSQL, Meta generation and Wit playback, then exits/re-enters Play Mode to verify recall and returning greetings. It invokes the reset operation and checks that the new ID survives another restart. A separate controller test drives the input action through short press, full hold and continued hold, and checks the shipped prefab’s visible HUD and persisted ID. Test input enters through the finalized transcript API; microphone recognition is covered separately by the conversation tests.
