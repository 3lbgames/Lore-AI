# NPC interaction

The Barbarian prefab starts an interaction when the player enters `NpcProximityTrigger.interactionRadius`. Set `OpeningIntent` and `OpeningSituation` on the Behavior Graph Agent’s Blackboard to control its generated opening; `FallbackText` supplies authored failure dialogue. Staying outside range for `departureGraceSeconds` (one second by default) cancels the interaction; entering again after that starts it again. Brief boundary crossings preserve the current speech. After speech finishes, the NPC keeps facing the player while they remain nearby, without repeating the line.

`Assets/_Behavior/NPC.asset` receives the interaction event and runs `Conversation.asset`. That subgraph keeps greeting and conversation inside `FacePlayerDuringInteraction`, which restores the previous facing settings and smoothly turns back to the saved pose when the interaction ends. The conversation loop keeps that scope open until departure is confirmed. The return uses the facing component’s turn duration and can be interrupted by a new interaction. `SpeakText` stops its own playback when it ends. The proximity trigger only publishes the player and interaction state; it contains no facing or speech behavior.

`SpeakText` accepts a speaker and arbitrary text. It uses `BaseAI_TextToSpeech` for playback, activity, and cancellation. The current prefab uses Wit; the graph node has no Wit dependency or greeting-specific behavior. The reusable prefab uses the original Wit UnityAudioPlayer; BaseScene overrides it with ElevenLabs as described below. Generated openings and replies require the Node service, PostgreSQL, and model access. Playback requires the configured speech provider credentials. The sample continues to listening if its opening fails.

When the speaker has an `NpcSpeechOutput`, `SpeakText` publishes the spoken text there and clears it when speech completes or is cancelled. The separate `NpcSpeechCaptionView` renders that state through the existing `UI_TextDisplay`.

The graphs use Unity Behavior 1.0.16 and can be edited in Unity's Behavior window.

Use **Tools → NPC Tests → Edit Mode** for unit checks and **Tools → NPC Tests → Routine Play Mode** for prefab/graph regressions. Routine tests use controlled speech and a loopback HTTP service, with no model, Wit network, Node, or database dependency. They share one native Play Mode session, with a fresh scene and service per test.

## Profile conversation

The Barbarian now has an `NpcCharacterDirector`, `NpcProxyClient`, and a `BarbarianProfile` asset. Edit the profile's personality, permitted facts, restrictions and voice preset in `Assets/_Behavior/BarbarianProfile.asset`. `NpcCharacterDirector` passes the optional voice ID through `BaseAI_TextToSpeech._ChangeVoice`; the configured adapter applies it.

The Conversation graph opens an interaction, selects the NPC when no other NPC is selected, faces the player, loads memory, and selects an authored relationship greeting. If `HasSpoken` is true, it attempts an NPC-initiated returning greeting with the intent and situation authored on `RequestNpcResponse` in `Conversation.asset`. Only a successful response replaces the authored greeting; failure retains it. If `HasSpoken` is false, the opening stays authored. The authored `Succeeder` lets a failed greeting continue to listening. It then repeats **Wait For NPC Transcript → Try In Order [Load Memory → Commit Input → Request → Remember Speech [Speak], Request Fallback → Remember Speech [Speak]]**. `NpcTurnScope` cancels its child branch when the selection revision changes, including an A → B → A switch within one frame. Request and speech nodes stop their own adapters when the graph ends them. `NpcCharacterDirector` holds interaction and selection state and coordinates campaign reset; normal conversation sequencing belongs to the graph.

For player turns, `RequestNpcResponse` applies the accepted relationship before releasing speech. If that update makes a previously unoffered action available and no action was selected, it makes one additional response request with the same committed input and updated revision/action list. The first draft is held while reconsideration is pending. Reconsideration is capped at one extra request; if that request fails, the first draft is spoken and recorded without an action, preserving the original conversational behavior. Accepted relationship changes remain saved, so the unlocked action can be offered on the next player turn. Departure, selection changes, or campaign reset cancel the pending turn without speaking the draft. The server assesses each input only once, so reconsideration cannot award relationship points twice. Ordinary turns and NPC-initiated reactions do not gain an extra call. Development builds emit `[NpcResponse]` logs with NPC ID, turn ID, request round, final proposed action, and first-draft fallback on reconsideration failure. Two request entries with the same turn ID followed by `round=2 completed` confirm a successful two-call turn; `fallback=round_1_draft` identifies second-call failure. These diagnostics omit player dialogue and credentials.

Queued world events take priority over the greeting. `TakeNpcWorldEvent` selects the event without removing it; `NpcWorldEventTurnScope` waits for memory, runs the authored reaction, and consumes the event only after success. Memory loading, campaign-state loading, response generation, and speech each get one automatic retry after a half-second pause. Speech retries reuse the generated text and do not repeat the model request or gameplay action. Departure or selection changes cancel the attempt. A second failure returns to listening without selecting the greeting. An interrupted or failed event remains available on the next encounter. The quest integration reports the outcome; the Conversation graph chooses how to react.

`Transcript`, `Response`, `RequestError`, `SpeechResult`, and `SpeechError` are transient Blackboard values. A failed request returns failure with its error code; the separate authored fallback branch reads blackboard `FallbackText`. Cancellation never selects that fallback. Speech results distinguish completed playback, failure, and cancellation; a caption is not evidence of audio delivery. A speech failure ends that turn and the repeat node returns to listening. Player input is committed before model generation. Only completed playback is restored as NPC speech; interrupted or failed playback records its status with no unconfirmed text.

Edit the saved graph assets in Unity’s Behavior window and configure profiles and prefab references in the Inspector; use source control for rollback.

The shipped scenes configure `NPC Speech Input` with `Core3lb.MetaStreamingSpeechToText`. In the Editor, enter Play Mode, approach the Barbarian, wait for its greeting, click **Talk to NPC**, and ask “Where can I get lodging for the night?”. Click **Finish speaking** to finalize the utterance. On Quest, hold the right index trigger to record and release to finish; the controller and `InputXR` button are configurable on `NpcSpeechControls`. One NPC owns the active conversation until departure; gameplay may explicitly call `SelectForConversation` to choose another nearby NPC. A recording captures its recipient and interaction at its start, and late transcripts are discarded after departure or selection change.

Start the local service using [the macOS and Windows service instructions](../../../../Server/npc-service/README.md). Provider credentials belong only in `Server/npc-service/.env`. Editor connection settings live in ignored `UserSettings/NpcService.local.json`; the Quest USB setup script copies those settings into an Android Development Build's private storage for local authentication. Release builds and LAN connections require Meta Platform user proof instead.

`NpcConversationPlayTests` covers unavailable-server recovery, single-recipient routing, exact transcript delivery, selection changes, and cached-audio watchdog behavior. The real-model playback/departure case is explicit and categorized `NpcLive`. Tests mute playback and restore listener volume and background-execution settings.

The headset displays recording and processing status below the center of view, with partial recognized words during capture. For USB testing without a Meta Platform app, use the development-only setup in `Server/npc-service/README.md`.

The recording display is the nested `Assets/_Prefabs/NpcSpeechStatus.prefab`. Edit its Canvas/TMP layout and `NpcSpeechStatusView` fields for wording, colors, camera offset, failure-display duration, and accepted-transcript duration. `NpcSpeechInput` only routes capture and exposes provider-neutral status; capture adapters implement `Core3lb.ISpeechCaptureStatus`. Red RECORDING follows the provider's actual recording state.

## Reskinning controls and speech output

- **Mic controls:** replace or disable `NpcSpeechControls` on `NpcSpeechInput.prefab` and the standalone `NPC Speech Input` object in `BaseScene`. A UI button, gesture, or controller adapter calls `NpcSpeechInput.BeginListening()` and `EndListening()`. Read `CanBeginListening`, `HasRecipient`, and `IsListening` to enable and label controls. The input component retains recipient/turn checks, timeout, and cancellation; custom controls must not call the transcription provider directly. Disabling the default controls while its XR button is held finishes that capture.
- **Mic status:** replace `NpcSpeechStatusView` and its nested prefab independently. Read the input's recording, starting, processing (`IsListening` after capture), partial-transcript, and failure state. Recording indicators must reflect `IsRecording`, not button-down state.
- **NPC output:** keep `NpcSpeechOutput` on the graph's speaker GameObject. Replace or disable `NpcSpeechCaptionView` to change the renderer or location. A custom view reads `output.Text` when enabled, subscribes to `output.Changed`, and unsubscribes when disabled. A null text means clear the display. Hiding a view does not cancel audio or erase the output state; re-enabling it restores the current text. Keep the view outside any panel it hides.

The current caption view references `UI_TextDisplay`; a replacement can render TMP text, a speech bubble, or a HUD without changing `SpeakText`. Output text becomes available when speech is requested, just as captions did before; it is not proof that audio has started or completed. The graph and speech adapter remain responsible for playback results and cancellation. `NpcCharacterDirector`, the conversation graphs, transcript routing, and the service request contract do not need to change for a reskin.

## Persistent conversation (US-03)

`Conversation.asset` runs the authored `Memory.asset` subgraph before greeting. `LoadNpcMemory` only loads acknowledged state through `NpcMemory` and the proxy. `RequestNpcResponse` generates returning openings from the profile, relationship, graph intent and recorded history; `RememberNpcSpeech` wraps playback to record delivery. `HasSpoken` identifies prior finalized player speech or completed NPC speech, including greetings and reactions. Interrupted or failed NPC speech and action outcomes alone do not count. The existing departure grace period still governs when another greeting begins.

`NpcCampaign` persists a campaign UUID per world and a writer UUID per installation in PlayerPrefs. On Quest, the panel above the left controller shows **Hold X to reset campaign**. Hold the left controller’s X button for two seconds; progress appears during the hold, releasing early cancels, and a completed hold shows a confirmation. Continued holding cannot trigger another reset. The Editor/desktop also retains its **Reset campaign** button. Both inputs call `NpcCampaignControls.ResetCampaign()`, which delegates to the director’s campaign operation: cancel the old interaction and reload fresh state. Previous campaigns remain stored. `NpcCampaignStatusView` owns only the HUD presentation; controller binding, hold duration, labels, controller anchor and panel offset are configurable. The view uses the rig’s tracked left-controller anchor by default, faces the camera for readability, and hides without an anchor. Reset requires the controller’s X button; no hand gesture is provided. `campaignId` on the director shows the current runtime ID; it is initialized from persistent settings rather than the authored scene value.

`NpcMemory` keeps an in-process queue of immutable event IDs and revision checks. The graph explicitly runs **Memory → CommitNpcInput → RequestNpcResponse → RememberNpcSpeech [SpeakText]**. The commit node saves exact finalized input before the generation node runs. The speech-memory scope records completion or interruption even when its child is aborted; `SpeakText` and `NpcSpeechOutput` remain generic playback and presentation components. A retry reuses the original event and receipt; load replaces the local `BaseAI_Conversation.acknowledgedHistory` projection. The legacy text-pair buffer contains player input and captioned NPC text, including lines whose audio was interrupted or failed. All scoped history is supplied by Node, so Unity never resubmits a second copy in model requests.

Storage errors remain visible beside the reset control and do not manufacture a new history. A later interaction or question retries pending in-process commits and reloads state. Full crash/offline journaling is deferred to US-14; events not acknowledged before the application exits are not guaranteed to survive. NPC speech records the full caption text even when audio is interrupted or fails; the delivery status describes audio, not whether the caption was available. `RememberNpcAction` records observed action descriptions and completed, failed, or interrupted outcomes independently of speech or selection. Gameplay action execution remains separate. See [graph authoring](../../../../docs/US03GraphAuthoring.md) for alternative presence reactions and NPC-initiated dialogue.

Run `NpcMemoryTests` for campaign identity and delivered-history projection checks. `NpcMemoryLiveTests` contains explicit `NpcLive` checks for controller reset, retry/interruption, and autonomous graph dialogue/action memory. These require local Node/PostgreSQL, Meta and Wit. The explicit `NpcMemoryRestartTests` stays in Edit Mode because it deliberately exits/re-enters Play Mode to verify recall and reset persistence. Run it separately.

Test input uses the finalized transcript API; these checks do not measure microphone-recognition quality or replace attended Quest checks.

## Meta streaming ASR prototype (US-07)

`Core3lb.MetaStreamingSpeechToText` streams microphone audio directly from Unity to Meta Model API (`muse-voice-transcribe-1.0`). Both the camera rig used by BaseScene/VillageScene and the standalone speech-input prefab use it. The former Wit adapter remains available for baseline comparisons.

Hold the right trigger to start a fresh push-to-talk session. Wait for **RECORDING** before speaking; release to finalize. The HUD replaces provisional text as recognition changes. Only the exact nonempty final transcript reaches `NpcSpeechInput`, which retains the selected NPC, interaction ID and turn revision checks. Partial text never enters dialogue or memory. Microphone capture starts before the network connection, buffering opening audio during connection and handshake. Releasing during that network startup preserves captured audio and finalizes after connecting. Releasing before microphone permission is granted still fails.

The transport waits for Meta's handshake acknowledgement, sends mono PCM16 at 24 kHz in paced 80 ms frames, drains queued audio on release, sends `endStream`, and waits for a final transcript and normal server close. Microphone buffering is four seconds; outbound audio is capped at twelve seconds to cover the ten-second connection/handshake budget. Overflow, missing audio, disconnect, invalid/empty results and timeouts fail instead of silently dropping speech. Cancellation, disable and application pause stop the microphone and abort the socket. Capture startup, provider-ready timing, microphone format, release/sample count, failures and interaction cancellations are logged without transcript contents or credentials. No Node audio route is involved.

Local setup: put the Model API key in ignored `Assets/Resources/MetaAsrKey.private.txt`. This prototype resource is bundled in local builds, just like the ElevenLabs credential; it is not suitable as a secret-distribution mechanism for a public release. Do not put the key into prefabs or scenes. Meta account access to Muse Voice Transcribe is required.

Run EditMode `MetaAsrTests` for protocol, buffering and resolved-scene wiring coverage. The `NpcRoutine` PlayMode category includes missing-configuration/disabled-provider checks. Run the explicit PlayMode `MetaAsrLiveTests.StreamsPrerecordedSpeechDirectlyFromUnity` separately; it uses credits and expects a 24 kHz mono signed PCM16 file named `villager-meta-asr.pcm` in `System.IO.Path.GetTempPath()`. Edit Mode is unsuitable for real-time pacing. See [ASR verification](../../../../docs/US07MetaAsrVerification.md) for evidence and remaining attended Quest acceptance.

## ElevenLabs prototype (US-07)

BaseScene's Barbarian and Mira currently inherit `Witt_TextToSpeech` from their prefabs, using the Wit voices authored in `NpcProfile.voice`. The ElevenLabs scene overrides have been removed. Speech input remains Meta streaming ASR. The Behavior Graph still calls the generic `SpeakText` node; switching the output provider requires no application-code changes. The ElevenLabs adapter remains available for alternative configurations and its focused tests.

The adapter calls ElevenLabs directly from Unity using `eleven_v4_turbo` and streamed mono 24 kHz signed 16-bit PCM. Playback starts after 0.75 seconds of queued audio (or the end of a shorter response), without waiting for the full response. Stopping speech, disabling the component, or leaving the interaction aborts the request and releases its audio clip. The queue is capped at 60 seconds of PCM; overflow fails explicitly instead of growing memory indefinitely. Open-ended bracketed voice directions pass to synthesis but are removed from captions. Captions still display the whole line; word timing and generated emotion cues are separate work. The adapter exposes first-audio, playback-start, download-time, and underrun measurements for diagnosis.

Local setup: place the API key alone in `Assets/Resources/ElevenLabsKey.private.txt`. This file and its `.meta` are excluded by `ignore.conf`; never paste the key into the scene. Unity includes the local resource in local builds, so this is a prototype credential arrangement. On another checkout, recreate that ignored file. The adapter also supports the inherited explicit key/ScriptableObject configuration when no local resource is present.

Configured voices: George (`JBFqnCBsd6RMkjVDRZzb`) for the Barbarian, Sarah (`EXAVITQu4vr4xnSDxMaL`) for Mira. The key needs Text to Speech access; User Read is only needed for usage checks.

Verification: `ElevenLabsPcmTests` covers chunk boundaries, signed PCM conversion, underrun recovery, and current BaseScene speech-provider wiring. `ElevenLabsPlayTests` contains a non-network missing-configuration test and an explicit `ElevenLabsLive` test that spends credits to verify streamed playback before download completion, successful completion, cancellation, and disabling during playback. Run live tests separately from `NpcRoutine`.

Speech provider code lives under `Assets/GenAI`: Meta ASR in `MetaASR`, Wit in `MetaWitt.AI`, and ElevenLabs in `ElevenLabs`. NPC runtime code uses `BaseAI_SpeechToText`, `BaseAI_TextToSpeech`, and optional `ISpeechCaptureStatus`; it does not reference speech-provider SDKs or concrete adapters. The director supplies an opaque voice ID through GroKit; each TTS adapter applies it. Provider choice belongs to prefab/scene configuration.

`NpcSpeechInput` emits `CaptureStarted` and `TranscriptAccepted` facts; it stores no caption or display timer. `NpcSpeechStatusView` owns the accepted-text cache and an Inspector-configurable `transcriptDuration` (eight seconds by default). It shows the exact accepted transcript while the NPC responds, clears it when a new capture starts or the selected recipient changes, and clears/subscribes/unsubscribes with the view lifecycle. Neither recognition nor playback waits for this UI timer.

NPC responses publish their caption before starting TTS. Completion, failure, timeout, or cancellation of audio no longer clears that text; the next response replaces it, and disabling the output clears it. Rendering remains in `NpcSpeechCaptionView`/`UI_TextDisplay`. A provider can supply a caption projection (for example, omitting spoken delivery cues), but missing or failed audio never suppresses the response text.

`BaseAI_TextToSpeech.speechStartTimeout` defaults to five seconds and is configurable per adapter. `SpeakText` applies it from submission until actual playback starts, using the provider-neutral `HasSpeechPlaybackStarted` fact. Once playback begins, a separate configurable `speechPlaybackStallTimeout` defaults to five seconds without a change in the provider-neutral `SpeechPlaybackProgress` counter. Healthy playback can exceed either interval. The adapter owns duration-aware completion; the application applies no fixed total playback cutoff. Streaming adapters report consumed audio, excluding silence inserted for underruns. Failures and timeouts stop audio, retain the caption, log a warning, and preserve the error outcome for the graph and memory instead of reporting successful audio.

The explicit `NpcSpeechFailureIntegrationTests.MissingElevenLabsKeyKeepsCaptionsAndConversationResponsive` test requires temporarily moving the ignored local ElevenLabs key resource and its metadata outside Assets, refreshing Unity, and restoring both afterward. It uses the actual ElevenLabs adapter with the controlled NPC service, checks a greeting plus two player turns, and verifies visible captions and renewed input readiness without TTS credentials.
